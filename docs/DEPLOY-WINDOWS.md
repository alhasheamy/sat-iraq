# دليل النشر من الصفر (لابتوب ويندوز)

الزمن المتوقع: **30 إلى 40 دقيقة**. التكلفة: **صفر**. لا تحتاج تثبيت أي برنامج ولا بطاقة دفع.

تحتاج فقط: متصفحًا (Chrome أو Edge)، وبريدًا إلكترونيًا، وحساب GitHub الذي لديك.

**الفكرة في ثلاث جمل:** ترفع الملفات إلى GitHub. GitHub يشغّل مهمة تلقائية كل 3 ساعات تجلب الطقس وتبني الموقع. المهمة تنشره على Cloudflare Pages ليصبح رابطًا عامًا مجانيًا.

---

## المرحلة 1: تجهيز الملفات

1. حمّل ملف المشروع `sat-iraq.zip` إلى جهازك.
2. انقر عليه بزر الفأرة الأيمن ثم **Extract All…** (استخراج الكل) ثم **Extract**.
3. ستحصل على مجلد اسمه `sat-iraq`. افتحه. يجب أن ترى بداخله مجلدات مثل `config` و`functions` و`scripts` و`web` و`docs`، وملفات مثل `package.json` و`README.md`.

> إن لم ترَ المجلد `.github`: في مستكشف الملفات اختر **View ← Show ← Hidden items**.

---

## المرحلة 2: إنشاء المستودع على GitHub ورفع الملفات

4. ادخل إلى **github.com** وسجّل دخولك.
5. اضغط علامة **+** أعلى يمين الصفحة ثم **New repository**.
6. املأ الحقول:
   - **Repository name:** `sat-iraq`
   - اختر **Public** (ضروري: GitHub Actions مجانية بلا حد للمستودعات العامة فقط).
   - **لا تفعّل** أيًّا من: Add a README / .gitignore / license (ملفاتنا فيها ما يلزم).
7. اضغط **Create repository**.
8. في الصفحة التي تظهر اضغط الرابط **uploading an existing file** (ضمن "Quick setup").
9. افتح مجلد `sat-iraq` المستخرج في مستكشف الملفات، واضغط **Ctrl + A** لتحديد كل ما بداخله، ثم **اسحبه** إلى صفحة GitHub في المتصفح. انتظر حتى ينتهي شريط الرفع ويظهر عدد الملفات.
10. في الأسفل اترك الخيار **Commit directly to the main branch** كما هو، واكتب في الخانة `first upload`، ثم اضغط **Commit changes**.
11. **تحقق:** في صفحة المستودع يجب أن ترى المجلدات: `.github` و`config` و`deploy` و`docs` و`functions` و`scripts` و`shared` و`tests` و`web`.

> **إن غاب المجلد `.github`** (أحيانًا لا يُرفع بالسحب): اضغط **Add file ← Create new file**، واكتب في خانة الاسم بالضبط `.github/workflows/deploy.yml` (الشرطة المائلة تنشئ المجلدين تلقائيًا). افتح الملف `sat-iraq\.github\workflows\deploy.yml` على جهازك بالمفكرة (Notepad)، انسخ كل محتواه والصقه في GitHub، ثم **Commit changes**.

> **ستظهر علامة ✗ حمراء بعد الرفع الأول في تبويب Actions. هذا متوقع.** السبب أننا لم نضف مفاتيح Cloudflare بعد. سنعيد التشغيل في المرحلة 5.

---

## المرحلة 3: حساب Cloudflare (مجاني بلا بطاقة)

12. افتح **dash.cloudflare.com/sign-up** وسجّل بالبريد وكلمة المرور فقط، ثم افتح رسالة التأكيد في بريدك واضغط الرابط.
13. إن عرض عليك Cloudflare **إضافة موقع أو نطاق** أو **ترقية خطة** أو **إضافة بطاقة**: تجاوز كل ذلك (Skip). **لا تفعّل خدمة R2** لأنها الخدمة الوحيدة التي تطلب وسيلة دفع، ولا نحتاجها.
14. **انسخ رقم الحساب (Account ID):** بعد تسجيل الدخول انظر إلى شريط العنوان في المتصفح. سيكون بالشكل `https://dash.cloudflare.com/` ثم **32 خانة من الأرقام والحروف** ثم `/home`. انسخ هذه الخانات الـ32 (وستجدها أيضًا في **Workers & Pages** في العمود الجانبي باسم Account ID). الصقها في المفكرة مؤقتًا.
15. **أنشئ مفتاح النشر (API Token):**
    1. اضغط أيقونة الملف الشخصي أعلى اليمين ثم **My Profile**.
    2. من القائمة اليسرى **API Tokens** ثم **Create Token**.
    3. انزل إلى **Create Custom Token** واضغط **Get started**.
    4. **Token name:** `github-sat-iraq`
    5. في **Permissions** اختر من القوائم الثلاث: **Account** ثم **Cloudflare Pages** ثم **Edit**.
    6. في **Account Resources** اختر **Include** ثم حسابك.
    7. اضغط **Continue to summary** ثم **Create Token**.
    8. **انسخ المفتاح فورًا** (يظهر مرة واحدة فقط) والصقه في المفكرة تحت رقم الحساب.

---

## المرحلة 4: إعطاء المفتاحين لـ GitHub

16. ارجع إلى مستودعك على GitHub ثم **Settings** (شريط التبويبات في الأعلى).
17. من القائمة اليسرى: **Secrets and variables ← Actions**.
18. اضغط **New repository secret** وأضف سرّين:

| Name (انسخه حرفيًا) | Secret (القيمة) |
|---|---|
| `CLOUDFLARE_API_TOKEN` | المفتاح الذي نسخته في الخطوة 15 |
| `CLOUDFLARE_ACCOUNT_ID` | الـ32 خانة من الخطوة 14 |

بعد إضافتهما **احذف المفكرة** التي فيها المفتاح.

---

## المرحلة 5: أول تشغيل ونشر

19. افتح تبويب **Actions** في المستودع. إن ظهرت رسالة **I understand my workflows, go ahead and enable them** اضغطها.
20. من القائمة اليسرى اختر **update-and-deploy** ثم اضغط **Run workflow** ثم الزر الأخضر **Run workflow**.
21. انتظر **5 إلى 10 دقائق** (أول مرة أبطأ). عند النجاح تظهر علامة ✓ خضراء.
22. اضغط على التشغيل الناجح. في الأعلى ستجد **Summary** فيه جدول الطبقات ونتيجة الطقس ورابط موقعك.
23. **رابط موقعك:** `https://اسم-المستخدم-sat-iraq.pages.dev` (اسم مستخدم GitHub بأحرف صغيرة، والشرطات بدل الشرطة السفلية). يظهر أيضًا في Cloudflare: **Workers & Pages** ثم المشروع.

> إن اختلف الرابط الفعلي في Cloudflare عن المتوقع (يحدث إن كان الاسم محجوزًا)، أضف متغيرًا: GitHub ← Settings ← Secrets and variables ← Actions ← تبويب **Variables** ← **New repository variable**: الاسم `SITE_URL` والقيمة الرابط الفعلي كاملًا بدون `/` في آخره.

---

## المرحلة 6: اختبار الموقع (5 دقائق)

افتح الرابط. ستظهر **صفحة الحالة المؤقتة** (الخريطة الكاملة يبنيها الذكاء الاصطناعي الآخر لاحقًا). افحص:

| ما تراه | المعنى |
|---|---|
| «البيانات»: الشبكة والمدن بالأخضر «قبل دقائق» | الطقس والغبار يُجلبان بنجاح |
| «غبار العراق»: مستوى ومدينة | الملخص العربي يعمل |
| جدول «طبقات الصور»: معظمها «جاهزة» | الاتصال بـ NASA يعمل. الطبقات «غير متاحة» تُخفى تلقائيًا وتُبلَّغ للمنفّذ |
| «المساعد الذكي»: «ربط الذكاء الاصطناعي: يعمل» | الدالة والربط سليمان |
| اكتب «أرني بغداد» واضغط أرسل | يعيد JSON فيه `actions` من نوع `fly_to` |

**اختبر الموقع أيضًا من شبكتين** (واي فاي منزلك وبيانات الجوال)، لأن بعض مزودي الإنترنت قد يحجبون نطاقات معينة، ولم أستطع اختبار ذلك من شبكتك.

---

## المرحلة 7 (اختيارية): عدّادات المساعد الذكي (KV)

بدونها يعمل المساعد، لكن لا يوجد سقف لكل مستخدم (سقف Cloudflare اليومي هو الحماية الوحيدة، وإذا نفد يعمل المحلل المحلي في المتصفح). **أنصح بإضافتها.**

24. في Cloudflare: **Storage & Databases ← Workers KV ← Create Instance** (أو Create namespace) واسمه `LIMITS_KV` ثم **Create**.
25. انسخ **ID** الخاص به (32 خانة من الأرقام والحروف a-f).
26. في GitHub: Settings ← Secrets and variables ← Actions ← تبويب **Variables** ← **New repository variable**: الاسم `KV_ID` والقيمة الـ32 خانة.
27. أعد تشغيل **update-and-deploy** (الخطوة 20). ثم افتح صفحة الحالة: يجب أن تقرأ «سقوف: مفعّلة (KV)».

> إن طلب Cloudflare بطاقة دفع عند إنشاء KV فتوقف وتجاوز هذه المرحلة. المشروع يعمل بدونها.
> إن فشل النشر برسالة صلاحيات بعد إضافة KV، عدّل المفتاح في Cloudflare وأضف له صلاحية **Account ← Workers KV Storage ← Edit** ثم أعد التشغيل.

## حل المشاكل الشائعة

| العرض | الحل |
|---|---|
| ✗ في Actions برسالة «السرّان … غير مضبوطين» | أعد المرحلة 4 وتأكد من كتابة الاسمين حرفيًا |
| `Authentication error` أو `code: 10000` | المفتاح بلا صلاحية **Cloudflare Pages: Edit**، أو رقم الحساب خاطئ. أنشئ مفتاحًا جديدًا (الخطوة 15) وحدّث السرّ |
| `Project not found` عند النشر | تعذّر إنشاء المشروع تلقائيًا. أنشئه يدويًا: Cloudflare ← **Workers & Pages ← Create ← Pages ← Upload assets**، اكتب اسم المشروع كما في الـ Summary، ارفع أي ملف صغير، ثم أعد التشغيل |
| الطقس «قديم» أو ناقص | افتح `رابطك/data/meta.json` وانظر الحقل `errors`. غالبًا حدّ مؤقت من Open-Meteo؛ يُحل في التشغيل التالي (بعد 3 ساعات) |
| طبقة «غير متاحة» في الجدول | طبيعي أحيانًا (معرّف تغيّر في NASA). انسخ الجدول من Summary وأرسله للذكاء الاصطناعي المنفّذ ليصحح `config/layers.json` |
| المساعد يعيد 503 `ai_unavailable` | افتح لوحة Workers AI في Cloudflare وتأكد أنك لم تتجاوز 10,000 Neuron اليوم (يتجدد 03:00 صباحًا بتوقيت العراق). في الأثناء يعمل المحلل المحلي |
| ظهر «Scheduled workflows disabled» | GitHub أوقف الجدولة بعد 60 يومًا بلا نشاط. اضغط **Enable workflow** في تبويب Actions. (المشروع يجدد نفسه تلقائيًا، لكن تفقّد مرة كل شهر) |

---

## الصيانة (5 دقائق شهريًا)

- افتح تبويب **Actions** وتأكد أن آخر تشغيلات خضراء.
- تفقّد لوحة Workers AI في Cloudflare في الأسبوع الأول لتعرف الاستهلاك الفعلي للمساعد.
- **لا تنشر مفتاح Cloudflare في أي مكان.** إن تسرّب فاحذفه من Cloudflare وأنشئ غيره وحدّث السرّ.
- كل ثلاثة أشهر: راجع ملف `LIMITS.md` وروابطه للتأكد أن الحدود المجانية لم تتغير.
- **لا تضف إعلانات أو أي دخل للموقع أبدًا**: خدمة الطقس (Open-Meteo) والخلفية (EOX) مجانيتان بشرط الاستخدام غير التجاري.
